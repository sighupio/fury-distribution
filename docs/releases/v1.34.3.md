# SIGHUP Distribution Release v1.34.3

Welcome to SD release `v1.34.3`.

The distribution is maintained with ❤️ by the team [SIGHUP by ReeVo](https://sighup.io/).

This patch release backports the `v1.36.0` module updates, features and fixes to the `v1.34` line, while keeping **Kubernetes 1.34** as the supported minor version. It targets Kubernetes `v1.34.12` on-premises (bumped from `1.34.8` in `v1.34.2`) and continues to support EKS `1.34`.

The `utilities` core module (Headlamp) and the `Immutable` kind introduced in the `v1.35` and `v1.36` lines are not part of this release.

Note that this release includes [Breaking Changes](#breaking-changes-).

## New features 🌟

- [[#575](https://github.com/sighupio/furyctl/issues/575)] OnPremises: add support for the new [`furyctl renew kubeconfigs`](https://github.com/sighupio/distribution/pull/588) command. It renews the kubeconfig file of the admin and the kubeconfig files of the users in `spec.kubernetes.advanced.users.names`. Then it downloads them to the working directory. A user that you add to the configuration file gets a kubeconfig file. It is not necessary to apply the kubernetes phase.

## Bug Fixes 🐛

- [[#577](https://github.com/sighupio/distribution/pull/577)] OnPremises: makes the admin.conf fetch in fetch-admin-conf-playbook.yaml pick the right master, and stops the playbook from failing on purpose to signal "cluster doesn't exist".
- [[#607](https://github.com/sighupio/distribution/pull/607)] DR module: fix velero triggering immediate backups after every `furyctl apply`.
- [[#597](https://github.com/sighupio/distribution/issues/597)] OnPremises: the API server now uses the OIDC groups prefix from the configuration file. Before this release, the installer ignored `spec.kubernetes.advanced.oidc.group_prefix` and always used `oidc:`. The new field is `groups_prefix`, the same name as `claimMappings.groups.prefix` in the API server `AuthenticationConfiguration`. `group_prefix` is deprecated, but it still works when `groups_prefix` is not set. Refer to the Breaking Changes section.
- [[#589](https://github.com/sighupio/distribution/issues/589)] All kinds: the schema now validates the `storageSize` fields of Prometheus, OpenSearch and MinIO as Kubernetes quantities, for example `10Gi`. A value like `10GB` now fails when furyctl validates the configuration, and not during the apply. The `retentionSize` field of Prometheus does not change, because it uses Prometheus units like `120GB`.

## Breaking changes 💔

- [[#597](https://github.com/sighupio/distribution/issues/597)] OnPremises: if you set `spec.kubernetes.advanced.oidc.group_prefix` to a value that is not `oidc:`, the OIDC group names change when you apply. Before this release, the API server always used `oidc:`, so your `RoleBinding` and `ClusterRoleBinding` objects probably use `oidc:`. Update these bindings to the prefix that you set before you apply, or the users of these groups lose access. If you did not set the field, or you set it to `oidc:`, nothing changes.
- Tracing: Tempo no longer supports the OpenCensus receiver.

## Known issues ⚠️

- OnPremises with Cilium: Cilium 1.18 and 1.19 have a bug ([cilium/cilium#44891](https://github.com/cilium/cilium/issues/44891)). When the upgrade replaces a Cilium pod that is not Ready, the `hubble-relay` pod on that node can stay not Ready, and `furyctl apply` waits on `deployment/hubble-relay`.

  Before you upgrade, make sure that all the Cilium pods are Ready:

  ```bash
  kubectl -n kube-system rollout status ds/cilium
  ```

  If the fault occurs, drain the node of the `hubble-relay` pod, reboot it, then uncordon it. A restart of the Cilium pod does not clear the fault.
